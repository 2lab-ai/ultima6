## Scope (what Korean mode covers)

- **Translated:** conversations, `look` text, books and signs, the executable's messages and labels, and the `u` program's opening, character-creation and transfer text.
- **Kept in English, by necessity:** words drawn inside pictures (main menu, title, intro art), roster and save names (Latin, 14-byte field), incantation syllables, runic text and the credits.
- **Needs the owner's own pack:** the game text is translated by a local tool from the owner's files. The public site never carries Korean game text; without a pack, Korean mode is Korean page UI over English game text.
- **Follow-ups, not v1:** a native `--locale ko` flag, and Galmuri14 at HD 2× (v1 draws Galmuri7 scaled by the HD layer).

Reading of "고대 영어틱하게": the original speaks in a faux-archaic English (thou, thee, art, hast). The Korean translation carries the same feel through archaic Korean speech levels (사극체). Modern Korean endings are not used.

## Measured facts

- **Where game text lives:**
  - the conversation scripts (`converse.a/.b`), text inside bytecode. It reaches the screen three ways:
    - text runs, printed byte by byte by `run_text` (`converse/run.rs:73-100`) through `put_char`;
    - table strings printed by `print_op`'s `d2` form, also byte by byte through `put_char` (`exec.rs:218-232`);
    - table strings copied into a string variable by `assign`'s `d2` form (`exec.rs:283-296`), printed later by `$n`;
  - `look.lzd` (`state.rs:183`);
  - `book.dat` (`objects/commands/look.rs:106-120`);
  - strings in the `game` executable (`GameImage::cstr`, about 15 loader sites);
  - the `u` program (opening, creation, transfer; its own text engine, `intro/text.rs`);
  - pictures: the main menu, title and intro art are drawn shapes (`intro/mod.rs:252-280`), so their words cannot be substituted.
- **The character path is `i16`, and its sign is meaningful** (`ui/printf.rs:74` `text_out`, `ui/print.rs:72` `put_raw`): a negative value flushes the pending line without a newline (`print.rs:199-205`; `printf.rs:113` is the `*` call site), and `put_raw` tests `c >= 0` before appending (`print.rs:85,101,111,114,187`). Hangul syllables (U+AC00–U+D7A3) are above `i16::MAX`, so in `i16` they would read as flushes.
  - The path is narrowed to a byte at: `line: [u8; 41]` (`ui/textstate.rs:7,21`), `draw_char(u8)` (`ui/text.rs:131`), `cell(c: u8)` (`print.rs:22`), `c as u8` (`print.rs:105,133,184`), the space and hyphen wrap tests (`print.rs:135,164`) and the transcript's `char::from` (`print.rs:33`). `line_ink` holds ink colours (`textstate.rs:22-23`), not characters.
  - The runic bit is `c |= 0x80` for `c > SPACE` (`print.rs:97`); it does nothing to `c >= 0x80` already. `printf` pads by bytes (`printf.rs:234`).
- **`$`/`#` output and `printf`'s own `%s` reach the screen through `put_raw_str` and `puts`** (`printf.rs:127,132,237,241`), the same functions game code calls with executable strings.
- **Article prefixes** ("a ", "an ", "the ") are added before object names (`objects/defs.rs:137-139`, `objects/names.rs:121-124`).
- **`Files` layers.** `Files::get` walks layers from the top, and each layer's `resolve` falls back to the bare name (`files.rs:59-63,91-96`), so a file in a higher layer shadows a base file of the same bare name. `get_in("base")` reads the base layer only (`files.rs:108`).
- **`book.dat`** holds u16 offsets, and each entry is read into a 0x2800-byte buffer (`objects/commands/look.rs:103,117-122`).
- **The `u` program's text path is byte-wide throughout:** `buf: Vec<u8>` (`intro/text.rs:30`), widths from `font.raw[4 + c]` (`:78-80`), `put_char`/`draw_glyph(u8)` (`:102,124`), and wrapping sums widths per byte (`:273-330`).
- **Typing is the real blocker.**
  - Keyword lists are matched against the bytes the player types (`converse/run.rs:24,125,149`).
  - `key_from_dom` rejects non-ASCII (`u6-web/src/lib.rs:121`); `raw_events` maps characters through the Amiga keymap and drops the rest (`ui/input.rs:125-155`).
  - `read_line` accepts only 0x20..=0x7e and stores `k as u8` in a 50-byte buffer (`ui/keyread.rs:158,203-207`); its echo calls `draw_char` directly (`:139`).
  - Op `f9` copies the typed input into a string variable (`converse/start.rs:309-320`), and the input slot can be printed with `$` (`converse/vars.rs:75`).
  - Keys reach the engine only from the focused canvas (`site/app.js:555-558`).
- **Font.** Galmuri7 (OFL-1.1, no Reserved Font Name) has all 11,172 syllables at an 8-px advance with glyphs ≤ 7×7, so one syllable fits one game cell. Galmuri14 fits one 16-px cell at HD 2×.
- **Window geometry.** Message rows are 17 cells (`ui/textstate.rs:124-130`). Korean at one syllable per cell carries more per row than English.

## Design

1. **Text path (engine; English stays byte-identical).**
   - **Character representation.** The path from `text_out` through `put_raw` to the line buffer becomes `i32`, keeping "negative = flush" as the one control value; every escape test compares against ASCII and is unchanged. `line` and `transcript_line` widen to `u16`, and so do `cell`, the three `c as u8` sites and the transcript's conversion; `draw_char` takes `u16`. Codes below 0x100 come from the game's `u6.ch`; codes from 0xAC00 come from the Hangul table, a type of its own beside `BitFont` (`u6_formats::font::HangulFont`, one 8 × 8 cell per syllable U+AC00..=U+D7A3), held in `UiState::hangul` and, for the `u` program, `TextCtx::hangul`; with no table a syllable is a blank cell. Controls never enter the line buffer.
   - A UTF-8 assembler in front of the escape layer, enabled only while a locale layer is active (`TextState.wide`). A byte ≥ 0x80 that does not start a valid sequence passes through unchanged, as today, so English fallback text is unchanged with `wide` on.
   - Guard the runic `|= 0x80` with `c < 0x80`, and make `printf` count cells instead of bytes.
   - **`printf`'s cell count** (with `wide` on; off, a field counts its bytes as before). A field's length is the cells it takes where it is put, counted on a copy of the assembler, the josa resolver, the last cell put and the escape layer's state: each code they let through is one cell, escape characters included (a field's escapes count as themselves, as its bytes do with `wide` off). The copy's last cell is the engine's, the last cell put into the line: a code goes to it as the escape layer and the line put it, so an escape character, hidden text and the braces of `@{…}` leave it as it was, `#n` and `$n` leave what they print, a digit in a runic window is no digit, and a space that the start of a wrapped row drops is no cell of the tail (a row that wraps at a space drops the spaces after it up to the first other code; a padding of spaces that wraps a started row (one pad more than the row has room for) does that, and leaves the tail on the cell before it; a padding that only fills the row does not wrap it; where the row then wraps follows from the field's own codes as the line lays them). A marker in a field follows the cell put before it. The count of a field whose own end is held (a UTF-8 sequence or a josa marker it begins and does not finish) is provisional: the held end is counted as if let out, one cell per code (its padding, or whatever comes next, lets it out). Where the text after the field completes it instead, the field is drawn as completed, and its cells can differ from its count in either direction: `%3s` with `\xea\xb0`, then `\x80` in the format, is one syllable for a count of two; a one-byte lead completed is one syllable, as counted; a josa marker begun (`{이`, then `/가}` in the format) can take its paired form, four cells for a count of two. That is another way the count is not the drawn width, beside the cases where no padding fits (below). A string split that way across a field and the text after it is not well formed, and the translation tool refuses it (§6). Elsewhere the count and the copy's last cell are the engine's at the field's end, for the padding chosen.
     - A left-aligned field is put before its padding, so it is counted from what is held: a syllable or a josa marker begun before the field and finished in it is the field's. Its cells do not depend on the padding, which is the width less them (none when they reach it).
     - A right-aligned field is put after its padding, and its cells depend on it. A padding of 1 or more first lets out what is held (it is the text before the field, so the field is counted from an empty assembler and resolver), ends an `@` just before the field (so its `{` opens no brace), and is laid out (it can wrap the row). A padding of 0 puts nothing and lets nothing out: the field goes on from what is held, after that `@`. With `cells(p)` the cells the field takes after a padding of `p` and `w` the width (at least 0), a padding `p` fits when `p = max(0, w - cells(p))`. The padding is found by iterating `p0 = max(0, w - cells(0))`, `p(k+1) = max(0, w - cells(pk))` and stopping at the first `p` that fits. A `p` that fits meets or exceeds the width (`p + cells(p) >= w`). Every `p` lies in `0..=w`, so the values repeat within `w + 2` steps. When they repeat with none that fits, the padding is 0 if something is held before the field (the assembler or the josa resolver holds a code), and else the smallest `p` of the cycle. Either way the field's cells fall short of the width: the padding chosen and the cells after it come to less than `w`. Write `f(p) = max(0, w - cells(p))`, and let `m` be the smallest `p` of the cycle. `f(m)` is in the cycle, so `f(m) >= m`, and no `p` of the cycle fits, so `f(m) > m >= 0`: `w - cells(m) > m`, and `m + cells(m) < w`. A padding of 0 where something is held falls short too: the values reach a cycle only when `p0 = f(0) > 0`, so `cells(0) < w`. That bounds the count, not the line drawn. The line can pass the count in two ways only: `#n` and `$n`, which can put more cells than their codes (above), and a field whose own end is held and completed by the text after it, which is drawn as completed (above). After a held `\xea`, `%5s/가}|` with the field `\xb0\x80a{이` counts four with no padding and five after any, so the paddings go 1, 0, 1 and, something being held, 0 is used; the format's `/가}` then completes the marker after `a`, and the field draws six cells, `가a이(가)`, the `|` after it (the row is seven). The line can also fall below the count, since some codes that are counted draw nothing; among them: escape characters (a back-quote, `<` and `>`, `&`, `%`, `^`, a keyword `@`, and the `@` and braces of `@{…}`), in Korean a `/` or `\` and the letters after it, hidden text while hidden, a newline (it puts no cell, and one the scroll does not skip ends the row), a space the start of a wrapped row drops, the space a wrapping row breaks at, and a short `#n` or `$n` (`#3` holding 2 puts one cell for its two codes, an empty `$1` none). A padding of 1 or more, with its first pad and whatever its size, lets out what is held and ends an `@`, a newline to skip and a pending capital; a `0` padding also ends the dropping of spaces at the start of a wrapped row (a `0` is no space). A padding of spaces that wraps a started row (one pad more than the row has room for) leaves the row after dropping the spaces the field first lays (only a code the line lays ends a drop); a padding that only fills the row does not wrap it; where the row then wraps follows from the field's own codes as the line lays them. No padding fits where the cells after the paddings tried send the values round a cycle. The cases met so far: a held sequence the field would complete (a UTF-8 lead, a josa marker begun), which a padding lets out first, so the field's codes are put apart; a `0` padding after a row left dropping spaces, whose `0`s end the drop, so the field's leading space is a cell and a marker after it takes the paired form; a newline to skip, which a padding ends, so the field's newline is put and ends a row that drops spaces, with the same effect; an `@` just before the field, which a padding ends, so the field's `{` opens no brace (`가@%5s` with `{가}{이/가}` counts four with no padding and seven after any, and the paddings go 1, 0, 1); digits joined across a dropped space, where a padding of spaces that wraps the row drops the field's leading space, so the field's zeros continue the number before the padding, and twenty or more trailing zeros have no reading, so a marker after them takes the paired form (fifteen cells ending in `1` before `%26s` with a space, twenty `0`s and `{이/가}`: 22 cells after paddings 0 to 2 and 25 after 3 or more, the paddings go 4, 1, 4, and 1 is used); hidden text completing a held sequence, whose completing codes are never laid, so the field's first laid code can be a space that a wrapping padding drops (after `aaaaaaaaa가&` and a held `\xea`, `%8s` with `\xb0\x80& {이/가}`: 7 cells with no padding, 8 after 1 to 7 and 5 after 8, the paddings go 1, 0, 1, and as something is held 0 is used). Where something is held, 0 keeps it for the field: short is preferred to broken, since each pad put lets out what is held first, and a padding would show the sequence's bytes or codes apart instead of the syllable or particle. After a held lead, a right-aligned field of width 2 that finishes the syllable takes one cell with no padding and two bytes after a padding of 1: no padding fits, and 0 is used, so the syllable is drawn whole, one cell short. Where nothing is held, the smallest padding of the cycle leaves the field's cells short of the width rather than past it: after 가's padding left a row dropping spaces, `%03s` with ` {이/가}` counts two with no padding (the dropped space and the particle, drawn `가`) and five after any padding of `0`s (` 이(가)`), the paddings go 1, 0, 1, and 0 is used, so the row shows `가|`. Where a padding of 1 or more fits, it is the first fixed point and is used, even with something held, though it lets the held sequence out: at width 3 the held-lead field above takes a padding of 1, and `\xea%3s` with the field `\xb0\x80` draws the lead byte, a space and the field's two bytes, apart.
     - A padding of 0 or less puts nothing and lets nothing out, so a syllable or a marker split across fields, or across the format and a field, still joins.
     - Padding is not text: the last cell the josa resolver reads stays the one before it, so a particle after a padded field follows the field, and one at the start of a right-aligned field follows the text before the padding.
   - **`@{…}`** (with `wide` on). `@` followed at once by `{` opens a brace highlight: the text up to its closing `}` takes the alert colour on every put (past a wrapped row, a flush, and `$n` or `#n` inside it), and the braces print nothing.
     - "At once" is read where the codes reach the escape layer: the next code it takes after the `@` is the `{`, and nothing is put between them. Any code between them ends the `@`'s claim (also one that hidden text drops), and so does a put from outside the escape layer (padding, a `printf` directive put as it is such as `%%`, a flush, a string put unescaped). A padding of 0 or less puts nothing, so an `@` at the end of a format still reaches a `{` at the start of a field; the end of a unit of text ends it. An `@` in hidden `&…&` text that is not shown is dropped and opens nothing. Text put while text output is off reaches neither the escape layer nor the line, so it ends nothing. `printf`'s cell count reads a field by the same rules (its copy of the escape layer keeps the hidden-text toggles).
     - The brace comes first. The `{` right after `@` goes to the escape layer before the josa resolver can take it, so it never starts a marker, and the braced text is plain text: `@{(으)로}` puts `(으)로`. A marker later inside the braced text resolves as anywhere. `printf`'s cell count reads a field the same way (`@{(으)로}` is seven cells).
     - A `{` later in an `@` keyword opens nothing; it is the keyword's.
     - Only a `}` the escape layer takes closes the brace. A josa marker's `}` is the marker's (the resolver takes the whole marker first, `ui/wide.rs` `Josa::feed`), so a marker inside the braced text leaves it open; a `}` inside hidden `&…&` text is dropped before it is read (`ui/printf.rs` `escape`).
     - A brace still open where the unit of text that opened it ends is closed there, and the text ink comes back. The units are a `printf` format (its fields included), a conversation's text run (the text bytes between two bytes that are not text, §2), what one conversation op puts (a table string, put one byte at a time) and a keyword block (its newline and its answer, whose text runs are units too). A unit closes only a brace it opened: a `printf` run while text put one byte at a time has a brace open leaves that brace open. The translation tool's gates still require every `@{` closed in its unit (§6).
     - Where any unit of text ends, what the assembler and the josa resolver still hold (a UTF-8 prefix, a marker not complete) is let out first, unchanged, as a malformed prefix is, in the colour in effect there (the brace's, when the unit's brace is open). Nothing joins the next unit; within one format, fields still join as above. So an `@` that ends a unit and a `{` that starts the next open no brace: the unit's end ends the `@`'s claim, and the `{` is the `@` keyword's, as with `wide` off.
   - Tests push U+AC00 and U+D7A3 through ordinary text, a runic window and the transcript, and check that each lands as one cell and `-1` still flushes. A lone 0x8f passes through.
   - A pack-only positional `%1$s`, and a josa resolver `{이/가}` `{은/는}` `{을/를}` `{과/와}` `{(으)로}` that looks at the last drawn syllable (batchim rule) and reads digits as Korean numbers. After anything that is not a Hangul syllable or a digit (a Latin name, for example), it writes the paired form, such as `이(가)`.
   - Plural markers `/` and `\` are dropped in Korean, and the article prefix is empty. These grammar rules belong to the pack's declared language (`meta.language`), not to `wide`: a pack declaring `en` keeps English articles and plurals while using the same lookup, decoding and rendering path.
   - Roster names stay Latin; the 14-byte save field is unchanged.
1b. **The `u` program's text (`intro/text.rs`).** Its proportional path iterates code points instead of bytes when `wide` is on. A Hangul syllable takes its glyph from the same Hangul table, drawn at the WOU font's height with an 8-px advance, and wrapping sums widths per glyph. With `wide` off, the path is byte-identical to today.
2. **Lookup keys.**
   - **The converse unit is one text run:** the bytes between two non-text bytes, with its inline escapes (`$n`, `#n`, `*`, `@`, `&`, `<`, `>`, `` ` ``) kept as placeholders. Ops are never moved, merged or skipped, so every op and every checkpoint yields runs exactly as in English. A sentence that the script splits across ops is translated as ordered fragments; the translator sees the whole script in order.
   - The runtime key is (archive, item, run offset). The base fingerprint pins the offsets. The pack also stores each run's hash64, checked once at load: a mismatch refuses the pack.
   - **Table strings** are keyed (archive, item, string offset). One hook in the table reader serves both `print_op d2` and `assign d2`; an assigned string must fit its slot's capacity (a pack gate).
   - **Executable and `u` strings** use a content hash, taken only at the outermost print call made by game code: `printf`'s format, `puts` and `put_raw_str` called from game code, and the `u` program's print entry. Output generated by an escape (`$n`, `#n`, `printf`'s `%s`) is never looked up. Logic never sees translated strings. Strings shorter than 3 bytes are not substituted.
   - `look.lzd` and `book.dat` are replaced whole, inside the pack's own layer. `look.lzd` is re-encoded with the existing `lzw::encode`.
   - A miss falls back to the original English. The miss counter counts only catalogued units and records the hash only.
   - Synthetic scripts test:
     - a run before and after an assignment that changes an interpolated variable;
     - a false `a1` skip that lands on `a2`, and an `a3` skip;
     - a `b0` jump into the middle of a script;
     - a `print_op d2` and an `assign d2` table string;
     - `*` inside a run.

     In each case the Korean output follows the English control flow exactly.
3. **Pack.**
   - One file `ko.u6lp` holding:
     - meta: language, tool version, base fingerprint over the source files;
     - the converse map with keyword aliases;
     - the strings map;
     - the replacement `look.lzd` and `book.dat`.
   - The engine mounts it as its own `Files::overlay` layer. Its replacement `look.lzd` and `book.dat` shadow the base files by bare name, which is how whole-file replacement works. No other file in the pack may share a bare name with a game file. The fingerprint reads the base through `get_in("base")`.
   - A fingerprint mismatch refuses the pack and names the part that differs. A malformed pack is refused with no change, under the 04 W6a limits.
4. **Typing Korean.**
   - A hidden `<input>` on the page receives IME composition. The page moves focus to it only while the engine reads a line (the line bit of `keys_owned`, 06), and back to the canvas when the line ends.
   - Composition is edited in the hidden input (Backspace inside a syllable edits the syllable). Only committed text reaches the engine, and Enter during composition commits first.
   - Committed text becomes a new `InputEvent::Text(String)` that bypasses the keymap and goes straight to `read_line`. `read_line` keeps a UTF-8 buffer with `INPUT_MAX` counted in characters, and echoes through the wide `put_raw` path, not `draw_char`.
   - The pack carries a Korean→English keyword alias map. It is applied inside `keywords()` (`run.rs:149`) to a copy used only for matching. The typed input itself is unchanged, so `f9` and `$` still show what the player typed. The typed word has its trailing particle (조사) stripped, and English keywords keep working.
   - Pack syntax `@{…}` marks a highlight explicitly, because `keyword_end` would otherwise swallow Korean particles (its rules are in §1).
5. **Language choice at start (page).**
   - A two-button gate "English / 한국어" sits above the drop area. It defaults from `navigator.language`, is stored in `localStorage`, and `<html lang>` follows it.
   - Switching restarts the game from the kept files; the save is untouched.
   - Without a pack, Korean shows the Korean page UI with English game text, plus one line pointing at `tools/i18n`.
   - The pack is dropped once and kept in IndexedDB under `locale:ko`. "Forget the Korean pack" sits next to the other forget buttons.
6. **Translation tool (`tools/i18n`, local).**
   - The extractor is shared with 09's NPC catalog: one catalog of runs and table strings, two consumers. It is a conversation disassembler (04 W3a's op table) that walks every script's ops, so the operand bytes inside expressions are never read as text.
     - Paths taken without a skip loop are decoded first; each skip-loop landing's path is then decoded on trial, its table uses included. A failed table check (address outside the script or in code, computed address, two kinds) refuses the script on a direct path and drops the landing on a trial path; a failed trial is tried again once the landings after it are in. Only kept paths reserve table bytes.
     - A table runs from its address up to its `b8`, the next table address, the script's end or direct code; one without a `b8` there also ends at landing code, but never before the last entry a constant index reads, including an index that runs on into it from the tables before it, nor before its first entry when a computed index reads it (any read of it needs one); a table with no entry still holds its address. A string address named inside another table's string is part of that table, and reads that string's rest; the table never ends before that string. The bytes a direct use reads are closed to landings: its needed entries, of either kind (up to a constant index's, the first for a computed index, an inner address's, all of them for a search), and for a direct search of tables with no `b8`, the bytes it reads on past them. A landing's table address there that does not chain with the direct read (a same-kind address at an entry's start, or a string address inside a string, chains; in the bytes a search reads on, only a same-kind address where they start does) drops the landings whose path names it, and landing code in a search's read-on bytes is closed as a table's bytes are; what a direct use reads is never cut, nor the script refused, for a landing. Every byte of a kept path's table is closed to landing paths: a landing that reaches one stops there, with one hazard that says it reached data.
     - A table wins over another landing's code inside it (the decode reruns with the table's bytes closed to landings), never over direct code or its own path's code: every byte the path reads, including code another landing decoded first that the path then joins (whose ops' tables the path names too). Of the landings waiting to be tried, the one at the lowest address where reading goes on is taken first, whatever order they were found in (a landing that only a higher landing's path leads to is found, and taken, after it; a failed trial is tried again only after every landing waiting or found meanwhile, higher ones included, has been tried), so the decode and the catalog depend on the script's bytes alone. Conflicts between landings are resolved by that order: of two landings whose code disagrees on a byte, or that read one address with two kinds, the one taken later is dropped; a landing whose code holds the address of a table another landing names stops there or is dropped at once when taken after the namer, and when taken first the table wins over its code in the next round, so of two landings each naming a table over the other's code the one taken first keeps its table. Bytes that no kept path's table holds any more are opened again and can no longer win. A constant index past the final tables, or a computed index or a search into a table with no entry (it reads past the table; a search stops at a `b8` at the address), drops every landing whose path runs that op (the one that decoded it and those that join it); the drop lifts, once, when a later round shows its cause gone (one landing per round, the lowest first; a landing dropped again after a lift stays dropped, since a trial of it alone can end otherwise than the round does). A search reads as the interpreter does, from its own address an entry at a time up to a `b8` at an entry's start: one from a `b8` reads nothing; any other reads every entry of its tables (so they never end at landing code), and with no `b8` in them reads on past the last one when nothing matches, where a `b8` that starts a table of either kind stops it. Onto any other item that too drops the landing (or, for a direct search, refuses the script, which only direct code or another direct table there can cause); past the script's end it is a hazard with the bytes it reads there.
     - The catalog (`u6-converse-catalog/3`, JSON) lists runs, table strings, names and keywords, each with its FNV-1a 64 hash. A run that a path enters mid-text is split there, and its parts carry `part_of` (the first part's offset), so one sentence stays one translation unit. An `a6` copy's index is resolved on into the tables that follow its table, and a computed index marks every string it can reach, so the slot check sees every copied string. A string an op reads from after its start lists those addresses (`inner`), since such a read prints the string's rest. Reading a catalog back checks each unit's text, length, hash and place, that the `part_of` groups are as written (contiguous, the first part linking to itself, the others to it), and that each string's inner addresses are inside it.
   - It writes a local coverage receipt by source category (conversations, look, books, executable strings, `u` program): units found, translated, excluded with a named reason, and missing. It holds counts and hashes only.
   - Pass 0: the LLM proposes a glossary (names by 외래어 표기법, common nouns rendered archaic). The owner reviews it, and it is frozen.
   - Pass A: the speakers file. Each speaker class is inferred from the script header, the look text and the object type, and the owner can override it.
   - Pass B: one script per call (200 units), plus about 25 calls for the other sources. Each call carries the style guide, the speaker's class and register, the glossary slice, the NPC's earlier lines and the script's runs in order.
   - The translator and the reviewer are different engines; for example, a Claude model translates and gpt-6-astra reviews.
   - Mechanical gates check structure only:
     - placeholder multiset equal;
     - every code point is a Hangul syllable or ASCII;
     - label strings fit their cell width;
     - josa markers are well formed, each unit read as the text layer reads it: `@{` first (the `{` right after `@` is the brace's, never a marker's), then the markers;
     - every `@{` is closed in its unit by a `}` the escape layer takes: not a josa marker's `}`, and not one inside hidden `&…&` text;
     - no `printf` directive has a partial UTF-8 sequence or an unfinished josa marker next to it, on either side (one a field ends with and the text after it completes makes the field's count provisional, §1);
     - keyword aliases are non-empty;
     - assigned table strings fit their slots;
     - the replacement `book.dat` keeps u16 offsets with each entry under 0x2800 bytes;
     - `*` and every other escape count as placeholders in the multiset check.
   - The register gate is a review by the second engine plus a 5% sample checked by the owner.
7. **Register (사극체) guide (committed, `tools/i18n/style-ko.md`).**
   - thou/thee/art/hast choose the speech level and the form of address; they have no word-for-word Korean.
   - The default address to the hero is 그대.
   - The class table maps speakers to endings:
     - royalty: 해라체;
     - nobles and mages: 하오체;
