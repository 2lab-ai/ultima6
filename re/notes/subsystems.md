# Amiga `game`: subsystems, main loop, porting order

Source: the classification in [functions.md](functions.md) (generated by
`tools/rea/classify.py`; per-function rows in `functions-*.md`). Addresses are image addresses
at base 0x00100000. "[likely]" = inferred from structure (callers, callees, globals), not read
line by line. Measured 2026-10-14.

## Boot chain

    0x100000 entry (SAS/C startup)  ->  0x101390 (jump)  ->  0x1535d8 __main  ->  0x1351d8 main()

`main()` 0x1351d8 sets up the machine and the world, then never returns from the command loop:

| step | function | what |
|---|---|---|
| 1 | 0x14ef06 | memory check (exits below 260000 bytes free), buffers, opens intuition + graphics, saves the system copper list, adds VBlank server "Ultima 6 Int", opens input.device (0x151c60) |
| 2 | 0x152e50, 0x14f16c | tile graphics: maptiles / tileindx / masktype / animmask, objtiles |
| 3 | 0x134f08 | animdata + tileflag tables |
| 4 | 0x1351d8 body | BOOK.DAT, U6.CH; "You must first create a character" if none |
| 5 | 0x105350 | load state: objlist, schedules, base tiles; party position; object blocks; view |
| 6 | 0x110878 / 0x110912 | start area music (MED player, hunk 0) |
| 7 | 0x1041d8 | command loop (below) |

Display and input bypass intuition/graphics calls: no call in `game` goes through the
IntuitionBase or GfxBase it opens. Display = own copper list (0x16236a writes COP1LC/COPJMP1,
0x162294 BEAMCON0); input = an input.device handler 0x151b08 whose events 0x151d00 maps from raw
key codes. Music = MED player in hunk 0 (CIA-B timer interrupt via ciab.resource, audio.device).

## Main loop and command dispatcher: 0x1041d8

One iteration (one player command):

1. 0x103f64 redraws the side panel for the current panel mode.
2. 0x10790a reads a key: it waits in 0x106bbc (keyboard/mouse events from the input handler,
   clicks on panels mapped to command codes); panel-navigation codes 0x90-0x9f are handled
   inside and never reach the dispatcher.
3. The loop maps the letter to a command code, prompts (`printf` 0x108658 to the message
   scroll) and, for target-taking commands, reads a second key/direction, then calls the
   handler.
4. End of turn: 0x1213de (actor turn scheduler) and 0x10348c; then the next iteration.

| key | code | handler | | key | code | handler |
|---|---|---|---|---|---|---|
| A | 0x81 | 0x124caa Attack | | T | 0x83 | 0x1127c4 Talk |
| B | 0x8a | 0x121c64 begin / 0x121d78 break off combat | | U | 0x88 | 0x1305e0 Use |
| C | 0x82 | 0x11af10 Cast | | 0 | - | party mode (all follow) |
| D | 0x86 | 0x12a226 Drop | | 1-9 | - | solo mode for member N |
| G | 0x85 | 0x12a7a4 Get | | space, Esc | - | pass (leader's moves = 0; party follows 0x11c910) |
| L | 0x84 | 0x1298b8 Look | | direction | 0x80 | 0x11d4ee walk one step |
| M | 0x87 | 0x12ae04 Move (push) | | 0x13 | 0xaa | 0x105716 Save (asks first) |
| R | 0x89 | 0x127b1a Rest | | 0x12 | - | 0x1052c8 Restore (asks first) |

Control codes (read as ASCII control keys [likely]): 0x05 "Exit Game?" sets code 0x12d, which
ends the loop; 0x08 help; 0x11 skips to the end-of-turn path; 0x16 version line; 0x1a sound
on/off (0x110912 / 0x110878).
Codes 0xd5-0xd7 and 0x119 are debug/cheat paths (coordinate dump, a hidden prompt, a clock
step, 0x135118). Ready/Unready (0x112052 / 0x1123d6) are reached from the inventory panel, not a
letter.

## World turn: actors, schedules, clock

| function | role |
|---|---|
| 0x1213de | turn scheduler: among the 256 actor slots near the party (within 0x28 tiles), the one with the most movement points acts next; NPC slots run 0x1200b0; when nobody has points left all are refilled and 0x10368a advances the clock |
| 0x1200b0 | NPC turn: reads the actor's current schedule entry (location) and walks toward it / performs its worktype; worktype-specific helpers live in hunk 13 (0x12500a..0x126f58) |
| 0x121826 | schedule selection (called from the clock): for actors 2..0xdf, finds the entry whose hour matches the current hour and whose weekday matches or is "any", stores the entry index, sets worktype 0x81 |
| 0x10368a | clock tick: torch/light timers, status timers, random events, date + wind line in the status area |
| 0x11d4ee | player step: direction, drunk wobble ("Hic!"), blocking, level transitions (0x11d1d4) |
| 0x11c910 | each party member follows the leader [likely] |

Global tables these share (offsets read off the code, meaning [likely]):

| where | meaning |
|---|---|
| 0x135588, 3 bytes per object | location: x = 10 bits, y = 10 bits, z = 4 bits (objects 0..255 are actors) |
| 0x137988, word per object | type (10 bits) + frame (6 bits) |
| 0x139188, byte per actor | worktype (0x81 = follow schedule, 0x80/0x83..0x86 = other modes) |
| 0x139988, 5 bytes per entry | schedule entry: low 5 bits hour, top 3 bits weekday (0 = any), then location |
| A4+0x48fe, word per actor | first schedule entry of the actor (next actor's value ends the range) |
| A4+0x47ec / A4+0x4b00 | party member actor numbers / party size |
| A4-0x7b78 / -0x7b76 / -0x7b74 | party leader x / y / z |
| A4-0x7b81 / -0x7b80 / -0x7b7f | hour / day / month |
| A4+0x400c / A4+0x430c, byte per actor | movement-point refill / current movement points |

## Dependency order for porting

Cross-subsystem direct-call edges (counted from the inventory) give these layers; port a layer
only after the ones above it. Cycles are named: they are ported together behind one interface.

| layer | subsystems | depends on | note |
|---|---|---|---|
| 0 leaves | runtime, util | - | runtime is replaced by Rust std; util = RNG 0x151ee4 / 0x151f06 |
| 1 platform | fileio, os, input, graphics, sound | runtime | graphics calls only fileio/os (+1 edge to ui); fileio calls ui only for disk-swap prompts |
| 2 text + panels | ui, inventory | graphics, objects (names) | cycle ui <-> objects: messages print object names (0x10eef8), object code prints via 0x108658 |
| 3 world data | map, objects | fileio, ui, graphics | cycle map <-> objects: view flags read objects, object blocks load per map region |
| 4 simulation | actors, schedules, party, time | objects, map, combat leaf helpers | cycles actors <-> combat (NPC worktypes in hunk 13) and time <-> combat (poison, death 0x1231be) |
| 5 interaction | converse, combat, magic, saveload | everything above | magic has the widest fan-out (ui 102, objects 72, combat 67 edges) |
| top | main, boot | all | 0x1041d8 and 0x1351d8 wire the rest together |

The hunk-13 leaf helpers (0x121fca, 0x121ff8, 0x122048, 0x1220f0, 0x122144, 0x122176,
0x1224ea, 0x121bce) are called by time, converse, panels and party code: port them with the
actor model (layer 4), not with combat.

## Milestone 1 set

Goal: boot into Britannia, draw the map view with objects and the party, walk with the keyboard,
NPCs follow schedules, talk to an NPC.

Method (in `classify.py`, `mark_milestone`): closure over direct calls from the startup 0x100000
and the input handler 0x151b08, not entering (a) the other command handlers (Attack, Cast,
Look, Get, Drop, Move, Use, Save, Restore, Rest, combat on/off, Ready, Unready), (b) magic and
music, (c) any combat function that itself calls something. The targets cut off are the stub
points: the port needs a no-op or minimal stand-in there.

Result: **361 functions** (20,197 of 33,047 pseudocode lines, 61%); 41 of them are SAS/C
runtime that the port replaces, leaving **320 game-side functions**. Confidence of their
subsystem: 75 high, 281 medium (module default), 5 low.

The milestone paths through it:

- boot: 0x1351d8 -> 0x14ef06, 0x152e50, 0x134f08, 0x105350 (state load), then 0x1041d8.
- draw: 0x102ef0 -> 0x109e74 (view flags) + 0x10202e (map window, objects) -> blitter
  0x153002 / 0x152ffa; panels 0x103f64 -> 0x110d2c / 0x1109e0.
- walk: 0x10790a -> 0x106bbc <- input 0x151b08 / 0x151d00; code 0x80 -> 0x11d4ee; followers
  0x11c910.
- NPCs: 0x1213de -> 0x1200b0 (schedule walk); 0x10368a -> 0x121826 (hourly schedule pick).
- talk: key T -> 0x1127c4 -> 0x114afa -> 0x133e5e / 0x133d3e (script, portrait) -> 0x1130a2 ->
  0x11404c; output 0x108658 / 0x108376.

Stub points (45): the 14 cut command handlers; magic 0x10674e, 0x115da4, 0x11612e, 0x116218,
0x116526, 0x11785e (spell-name/spellbook code reached from the event loop and from converse);
music 0x110878, 0x110912 and MED entries 0x100f7c, 0x100f96; 21 further non-leaf combat
functions, mostly NPC worktype behaviours called from 0x1200b0 (0x12500a..0x126f58) plus damage/death
paths (0x1231be, 0x1230ce, 0x12395a). The full list is the `S` marks in `functions-*.md` and
`milestone1_stub` in the inventory JSON.

Low-confidence links on the paths: the role of 0x10202e (map render) and 0x102c90 is [likely];
0x11c910 (follow) [likely]; hunk 17 (4 unknown functions) is pulled in by object and map code
and has no string evidence.

## Gaps and caveats

- Coverage: 599 functions + 784 jump stubs = all 1383 REA procedures. Not every routine is a
  REA procedure: the VBlank server body that 0x14ef06 installs (code label 0x14f27a) has none.
  Procedures with no direct caller (reached through a pointer or not at all): 0x100234 (MED
  interrupt), 0x100e96, 0x1017aa, 0x105e94, 0x109b6c, 0x10d340, 0x112010, 0x1220c6, 0x134c80,
  0x134db0, 0x134dd4, 0x151b08 (input handler), 0x162294.
- OS calls take their arguments in registers, which the decompile does not show; library and
  device names and most file names were tied to functions from the image bytes (LEA/PEA
  d16(PC) and relocated absolute operands), not from the pseudocode.
- 87 of 515 strings are not tied to a function: the spell-name table past the 24 slots the
  tool reads from a referenced table offset, combat-mode names, song file names, the hunk-21
  save/restore disk prompts, `.bmp` names, and a few singles.
- Module defaults carry most rows (medium confidence). A function whose module default is
  wrong (a helper filed in another source file) is only caught by curated rows or strings.
- A4 = 0x15B6F0 [likely] (SAS/C small data). Of 213 small-data offsets that hit a listed
  string, 171 land on its first byte; the other 42 land inside the `savegame/objblk??` name
  templates where the code patches the block letters. Both fit the assumed base.
